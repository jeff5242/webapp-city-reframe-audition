# 副市長指示｜九字訣與多階段方向（2026-08-18 demo 後）

> 來源：8/18 副市長 demo 後口頭指示（與會轉述）。本文件把指示對照我方系統現況、理事長框架與補助計畫書，標出可直接呼應處與待確認事項。

---

## 一、九字訣 × 我方能力對照

| 字訣 | 副市長原意 | 我方對應 | 現況 |
|---|---|---|---|
| **有沒有** | 該有的文件有沒有附 | **形式齊備性檢核**：DOC 文件存在、PB-DOC 附錄必附、FORM 欄位、FMT 格式母版（18 章 24 附錄） | ✅ 已上線（FMT 原型待整合） |
| **對不對** | 填寫內容與前後呼應對不對 | **內容一致性比對＋算式驗算**：CALC 法規門檻（獎勵上限/停車位）、CONS 前後一致、跨文件比對、法規年版對應 | ✅ 已上線 |
| **好不好** | 資料齊備後，規劃方向是否值得鼓勵 | **實質評價——屬審議會／人的判斷域**。AI 不判好不好（理事長紅線：不涉實質裁量），但可供**判斷素材**：同類案件統計比對（已有 peer stats）、歷年審議決議類案提示（第二期決議累積庫） | 🔶 素材面部分已有；決議庫屬第二期 |

> **關鍵定位**：九字訣前六字（有沒有／對不對）＝ AI 可確定性協助的範圍，與理事長第一階段功能一、二**完全重合**；「好不好」AI 只遞素材、不給結論——這個切分正好同時滿足副市長的期待與理事長的紅線，對外論述可以直接這樣講。

## 二、多階段延伸（四個階段）

副市長：只在收件時做內容審議效果有限，希望延伸至**四個部分**（含收件審議、審檢等，全程可隨時調用）。

**⚠️ 待確認**：確切四階段名稱與會者未記全。兩個可能解讀（下次會議或請華電/學會確認）：

- **解讀 A｜審查流程階段**：① 收件／掛件（形式審查）→ ② 幹事會審檢（協審）→ ③ 審議會審議 → ④ 核定後（修正核對／執行追蹤）
- **解讀 B｜計畫書生命週期**：① 事業概要 → ② 事業計畫 → ③ 權利變換 → ④ 變更設計

兩個解讀我方架構都接得住：

| 支撐能力 | 說明 |
|---|---|
| 格式母版多文件 | 事業概要／事業計畫／權變三份 schema **已產出**（解讀 B 直接可用） |
| 檢核方式依階段而異 | playbook 規則外部化——各階段掛不同規則集，改設定不改程式 |
| 「隨時調出來使用」 | 檢核引擎已 API 化（/audit），可包裝為各階段皆可呼叫的工具服務（呼應計畫書 A4 Orchestration Agent 的 tool-use 設計與 W1 工具化） |
| 版次差異比對 | 同案多階段/多版次 diff 已上線——審檢後修正重送的核對正是現成場景 |

## 三、與理事長框架的張力（需三方對齊）

| | 理事長（115.08.12） | 副市長（2026-08-18） |
|---|---|---|
| 適用範圍 | **限縮**：分案之前的收件端前處理（避「AI 參與審查」疑慮） | **擴張**：四階段全程可用 |
| 相容解法 | 各階段都定位為「該階段的**行政整理／檢核工具**」——AI 始終只標示疑義供承辦參考，不因階段後移而升格為審查判斷。「前處理」是收件階段的名字，其後階段可稱「審檢輔助檢核」「修正核對」等，**原則（僅標疑義、不生法律效果、責任歸機關）全程不變** | |

> 建議：向理事長回報副市長指示時，用「同一套上位原則、延伸到各階段的檢核工具」框架，避免被解讀為推翻「前處理」定位。

## 四、對補助計畫書／簡報的影響

1. **利多**：副市長「多階段、隨時調用」＝計畫書「一次開發、可複製擴散」的縱向版（跨階段）＋ A4 Agent tool-use 架構的直接背書；審查簡報可加一句「市府高層已指示延伸多階段應用」。
2. **九字訣可當對外敘事骨架**：市府版簡報下一版建議用「有沒有／對不對」組織功能頁（比理事長的功能名更好記、且是副市長自己的話）。
3. **第二期「決議累積」價值上升**：「好不好」的判斷素材（類案提示）正是第二期主打——爭取第二期的論述有了副市長背書。
4. **待辦**：確認四階段確切內容 → 更新簡報與計畫書的階段圖。
